# 团队知识库 Wiki Schema · 首版模板

> 交付物示例。真实项目里，这份模板由知识库负责人维护，并通过「Wiki → 编译 Schema」导入。

## 页面类型

| 类型 | 用途 | 必备段落 |
|---|---|---|
| entity | 人、系统、产品、项目等具体对象 | 定义、职责、相关对象 |
| concept | 方法、术语、指标 | 一句话定义、使用场景、反例 |
| summary | 一份素材的结构化摘要 | 核心结论、关键数据、来源 |
| synthesis | 跨素材的综合判断 | 共识、分歧、待验证问题 |

## slug 规范

- 全部小写，单词之间用 `-`；
- 概念页使用术语本身，例如 `spaced-repetition`；
- 项目页使用「项目-范围」，例如 `team-kb-in-three-weeks`；
- 改名时保留旧 slug，并新增一页「重定向说明」。

## 引用规范

- 正文使用 `[[slug]]` 引用其他页面；
- 引用必须带上下文，禁止只写一行链接；
- 每个概念页至少有一个入链和一个出链；
- 孤立页面在健康检查中视为错误。

## 质量标准

1. 每个定义都能被新人直接执行或验证；
2. 数字必须带口径与时间；
3. 冲突内容并列呈现，不静默覆盖；
4. 人工编辑过的页面由 `human_edited` 保护。

## 导入流程

1. 在「笔记」中完成素材整理与去重；
2. 在「编译任务」中确认解析质量；
3. 执行 Wiki 编译，抽查新建页面；
4. 运行健康检查，处理孤立页与断链；
5. 每周复盘一次知识库健康度。
