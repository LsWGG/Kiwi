# 组件插件对现有系统的影响分析

本文对应「设置 → 插件与区块」中组件插件、预览、导入导出与内置组件打包能力，
记录新增插件运行时对既有功能的影响、回退行为与验证要点。Kiwi 不再支持模板插件。

---

## 1. 数据模型与迁移

新增迁移 `e3f4a5b6c7d8_plugin_components`，只对 `plugins` 表做增量列：

| 列 | 默认值 | 说明 |
|---|---|---|
| `kind` | `'template'` | 迁移默认值；旧记录保留但不再展示 |
| `entry` | `''` | 组件入口路径 |
| `script` | `''` | 入口 ESM 原文 |
| `style` | `''` | 可选样式原文 |

- 不新增表、不改既有列、不重写 JSONB `manifest`，升级可原地完成。
- 旧插件读取路径（`/api/plugins`、`/blocks`、编辑器斜杠菜单）字段只增不减。
- 回滚：`alembic downgrade` 仅删除新列；已导入组件插件的 manifest 仍在 `manifest` 列，
  但无法再被渲染（预期行为）。
- 部署顺序：先执行迁移再上线新后端。旧后端面对新列不会读取，兼容窗口内可回滚后端。

## 2. 插件类型收窄为组件插件

- 新的 manifest schema 只接受 `kind: "component"`；模板 manifest 在导入预检阶段即被拒绝。
- 组件插件必须以 zip 交付，且包内提供入口 ESM；裸 JSON 导入返回 `400`。
- 已移除 `POST /api/plugins`；组件插件统一走 `POST /api/plugins/import`，确保脚本与
  manifest 同源落库。
- 历史模板记录保留在 `plugins` 表中，不做破坏性删除；`GET /api/plugins`、
  `GET /api/plugins/blocks` 与设置页均按 `kind = component` 过滤，因此不可见、也不会进入
  编辑器菜单。
- `PATCH /api/plugins/{id}` 只更新元信息、`enabled` 或整体替换区块定义，不会清空入口脚本。
- 导入覆盖同 key 插件时保留 `enabled` 状态。

## 3. 内置扩展组件

- 内置组件的启停继续使用 `system_settings.editor_disabled_extensions`，插件表与之独立。
- 新增的导出能力是只读操作，不改变启停状态、不影响编辑器渲染。
- 内置组件在编辑器中仍走原有专用节点；导出包只是参考，不会自动注册成第三方插件。
- 设置页把内置组件与第三方插件分区展示，二者开关互不联动。

## 4. 编辑器 schema 与 Markdown 往返

- 新增统一节点 `kiwiPluginBlock`（atom / selectable / draggable），属性为
  `pluginKey` / `blockType` / `props`。
- 任意插件、任意区块共用这一节点，**安装新插件不需要改 Tiptap schema，也不触发历史文档重建**。
- 正文保存为 `kiwi-plugin` 围栏：

  ````markdown
  ```kiwi-plugin
  {"plugin":"counter","block":"counter","props":{"count":3}}
  ```
  ````

- 解析 / 序列化都经过显式 fence 规则，与图册、日历、数据表等内置围栏共存；
  `kiwi-plugin` 规则先于内置规则匹配，未知或损坏的 JSON 会降级为空占位而不是抛错。
- props 以 JSON 保存，刷新、导出、搜索、双向链接均按普通 Markdown 处理。
- 区块支持 `align: left | center | right`（默认左对齐，缺省不写入 JSON）。
  编辑器中选中区块即可切换；阅读视图与分享占位读取同一字段，插件组件本身不需要
  感知对齐，也不应写死宽度 / 外边距破坏居中效果。

## 5. 阅读视图与公开分享

| 场景 | 是否执行插件 | 行为 |
|---|---|---|
| 编辑器 | 是 | 挂载真实组件，可交互，props 写回正文 |
| 工作区阅读视图 | 是 | 只读挂载已启用插件（`readonly=true`） |
| 设置页预览 | 是 | 允许加载已安装但停用的插件，交互只改本地副本 |
| 公开只读分享页 | 否 | 只输出静态占位与插件名，避免向未登录访问者下发可执行代码 |
| 其他静态导出 | 否 | 围栏保留，展示占位 |

公开分享页的 UI 与既有静态渲染一致，不新增鉴权要求，也不改变 `/media` 的访问策略。

## 6. 停用、卸载与失败降级

- 停用插件：区块立即从斜杠菜单 / 工具栏消失；已插入区块显示「插件已停用」静态卡片。
- 删除插件：注册记录与运行时缓存移除；正文中的围栏与 props 原样保留。
- 插件脚本加载失败、`setup` 未返回合法注册表、组件渲染抛错：
  - 宿主 `onErrorCaptured` 捕获并显示错误文案；
  - 不影响同页其他区块、编辑器输入、自动保存；
  - 卡片提供 props 展开与删除入口，便于清理。
- 重新安装同 key 插件后，旧区块自动恢复渲染。

## 7. 性能

- 插件列表 / 区块列表按需加载，编辑器首次打开不阻塞。
- 组件运行时使用动态 `import()`，只加载已启用组件插件的入口脚本。
- 样式按插件注入 `<link>`，卸载 / 覆盖时移除旧链接，避免重复累积。
- 脚本与样式 URL 带 `updated_at` 版本参数，更新插件即失效旧缓存；服务端响应使用
  `Cache-Control: no-cache`，避免升级后仍执行旧代码。
- 单个入口脚本上限 2MB、样式 512KB、整包 5MB，防止误导入超大资源拖慢编辑器。

## 8. 安全边界

- 服务端只解析 JSON / ZIP，不执行插件脚本、不代理插件网络请求。
- zip 解析拒绝绝对路径、`..` 穿越、目录入口与超限文件。
- `bundle.js` / `style.css` 带 `X-Content-Type-Options: nosniff`，按文本类型下发。
- 组件插件属于第三方代码：导入弹窗明确提示其可在浏览器访问页面数据；停用 / 删除可逆。
- 公开分享页不加载插件运行时，避免代码执行面暴露给匿名访问者。
- 插件脚本与笔记数据同源部署，不额外引入跨域凭据或外链脚本。

## 9. 样式、主题色与交互隔离

- 插件样式为全局 CSS，规范要求类名前缀（示例使用 `.kiwi-counter`）。
- 插件颜色必须跟随系统主题色：CSS 使用 `--kiwi-*` 变量，canvas / SVG 使用 `host.theme`
  （`accent` / `accentStrong` / `accentSoft` / `shade()` / `version`）。主题切换与学习模式
  切换会同步更新 CSS 变量并递增主题版本，插件无需自行监听设置。
- 编辑器自身样式不依赖插件类名；插件卸载后其 `<link>` 被移除。
- 组件容器由宿主提供选中态、只读态与降级卡片样式，第三方组件无需重复实现。
- 斜杠菜单与工具栏把「扩展组件」与「插件区块」分组，避免插件数量增长后混淆来源。

## 10. 失败模式与已知限制

| 场景 | 现状 | 说明 |
|---|---|---|
| 插件脚本使用裸 `import "vue"` | 加载失败并显示降级卡片 | 浏览器无法解析裸模块，规范要求使用 `host.vue` |
| 插件脚本在服务端被预览 / 抓取 | 不会执行 | 仅浏览器端 `import()` |
| 停用后打开含该区块的笔记 | 显示占位 | 数据保留，重新启用即恢复 |
| 公开分享页 | 静态占位 | 设计上不执行第三方代码 |
| 插件版本更新 | 自动失效缓存 | 依赖 `updated_at` 时间戳 |
| 插件间样式冲突 | 规范约束 | 无法在技术上完全隔离全局 CSS |
| 插件访问敏感页面数据 | 浏览器沙箱内可行 | 依赖用户只安装可信插件 |

## 11. 验证清单

后端：

- `uvx ruff check`
- `uv run --extra dev pytest`（含 `tests/test_plugin_components.py` 与 `tests/test_plugins.py`）
- 迁移在测试库执行到 `head`；组件 zip 导入 / 预检 / 导出往返、模板 manifest 被拒绝

前端：

- `vue-tsc -b --noEmit`
- `vite build`
- 设置页：导入预检警告、导入后预览、单插件导出、内置单个 / 全部导出
- 编辑器：斜杠菜单与工具栏插入组件区块、props 更新、刷新后保留
- 阅读视图只读渲染；公开分享页占位；停用 / 删除后降级；重新启用恢复
- 既有内置组件启停不回归；设置页不再出现模板插件创建 / 编辑入口

手工核对时使用测试库 `kiwi_locktest` 与临时插件，验证后通过 API 清理，避免污染真实数据。
