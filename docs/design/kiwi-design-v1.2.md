## 1. 项目概述

### 1.1 产品定位

Kiwi 是一款面向个人用户的**知识编译与检索系统**。它不满足于"把笔记存起来、问答时临时翻找"的传统笔记 + RAG 模式，而是将用户导入的原始资料在入库阶段就由大模型**编译**为结构化、交叉链接的 Wiki 知识页面，使知识在长期使用中不断沉淀、互相引用、产生复利。用户既可以把它当作笔记工具，也可以把它当作一个会"越用越懂你"的私人知识助手，还可以把它当作检验自身掌握程度的学习系统。

### 1.2 核心理念

- **知识编译优先**：原始素材保持不可变，大模型将其增量编译为 Wiki 页面，查询时优先基于编译产物回答，而非每次从头检索碎片。
- **检索保底**：向量检索作为低延迟的保底召回层，同时为编译阶段提供原料。
- **知识库为边界**：所有素材、Wiki 页面、笔记、对话检索都归属到明确的知识库，用户可以按知识库独立管理和按范围检索。
- **模型可配置**：大模型连接在系统级、知识库级、页面级三层可配置，用户可自由切换模型驱动编译与问答。
- **双模工作台**：编辑模式负责知识的生产与维护，学习模式负责知识的消费与检验，两者共享数据但各自拥有独立的界面与操作范式。
- **画像驱动的学习闭环**：学习模式以冷启动对话采集的学习画像为起点，以考试场景模板为契约，以动态出题和双形态训练为手段，以掌握度和计划引擎为调度，把"知识库"延伸为"学习系统"。

### 1.3 目标用户

以个人知识管理为主的用户：研究者、开发者、学生、内容创作者。典型场景包括：把散落在语雀、本地 PDF、Word 文档中的资料统一导入；让大模型把资料编译成可浏览的 Wiki；在对话中跨知识库提问；以软考高项/中项、PMP 等考试为目标，用学习模式检验和提升自己。

### 1.4 命名由来

"Kiwi" 取自猕猴桃这一小型、高密度、可切片的果实，对应系统的三个特征：**轻量个人规模**、**知识经过蒸馏浓缩**、**可按知识库切片检索**。

## 2. 设计出发点

### 2.1 纯 RAG 的结构性局限

传统 RAG 的典型流程是"分块 → 向量化 → 查询时检索 top-k → 拼入 Prompt"。它在个人知识库场景中有几个结构性痛点：分块丢失上下文关系、Embedding 相似度不等于语义相关、同一份文档每次查询都要 LLM 重新理解、查询之间不存在持续构建的持久化结构。

### 2.2 LLM Wiki 编译范式

Karpathy 提出的 LLM Wiki 范式将 RAG 从"解释器模式"升级为"编译器模式"：入库时就让 LLM 把原始素材编译成结构化的、交叉链接的 Markdown Wiki，查询时直接基于编译产物展开。其核心是三层分离——**Raw Sources（不可变原始资料）→ Wiki（LLM 维护的 Markdown 知识层）→ Schema（行为契约）**，以及三个操作 **ingest / query / lint**。一个新来源进入时，LLM 会通读现有 Wiki，找出与新内容的交集，更新相关页面——一个新来源可能触及 10–15 个现有页面，知识因此产生"复利"。

### 2.3 学习场景的特殊性

学习不是"随机抽题"。真实的学习目标（如软考高项、中项、PMP）有明确的题型结构、评分规则和合格标准；不同用户的当前水平、时间预算、薄弱环节各不相同；学习前期需要逐个击破知识点，后期需要整卷模拟检验水平。因此学习模式不能是固定题库，而必须是**画像驱动、场景对齐、动态生成、计划调度**的自适应系统。

### 2.4 Kiwi 的混合策略

- **知识层**：LLM Wiki 编译层为主 + 向量检索保底召回；
- **交互层**：编辑模式与学习模式双工作台，共享数据、独立界面；
- **学习层**：学习画像 + 考试场景模板 + 动态出题引擎 + 双形态训练 + 计划引擎，构成完整学习闭环。

### 3.2 分层说明

- **表现层**：Vue 3 单页应用，编辑模式与学习模式共享路由外壳，内部各自维护视图集合。
- **接口层**：FastAPI 提供 REST + SSE 接口，按业务域拆分 Router。
- **服务层**：领域服务封装业务逻辑。ImportAdapter 负责多源归一化，WikiCompiler 负责编译，RAGPipeline 负责检索与回答组装，QuestionEngine 负责动态出题与组卷，GradingEngine 负责判分，StudyPlanner 负责学习计划决策，WebResearch 负责联网核查。
- **编排层**：LangGraph 管理 ingest / query / learn 的多步状态机。
- **异步层**：Celery + Redis 执行解析、编译、出题、组卷、判分、联网核查等重任务，进度通过事件流推送。
- **存储层**：PostgreSQL 是业务事实源，Qdrant 是可重建的向量索引，对象存储保存原始文件与解析产物。

## 4. 双模设计：编辑模式与学习模式

### 4.1 双模定位

| 维度 | 编辑模式（Build Mode） | 学习模式（Learn Mode） |
|---|---|---|
| **活动本质** | 知识生产与维护 | 知识消费与检验 |
| **用户目标** | 把素材变成结构化的 Wiki，保持知识库健康 | 在目标场景下具备通过考试或掌握知识的能力 |
| **心智状态** | 开放、发散、多任务并行 | 专注、收敛、单任务推进 |
| **典型操作** | 写笔记、导入素材、触发编译、修 Wiki、看图谱 | 冷启动对话、渐进训练、仿真考试、看报告、复习到期知识点 |
| **信息密度** | 高（多面板、工具栏、状态提示） | 低（一次只呈现一个知识点、一道题或一份试卷） |
| **成功标准** | 知识库结构更完整、引用更丰富 | 掌握度提升、仿真考试得分提升、复习队列清空、错题减少 |

两种活动对界面节奏、视觉干扰、操作路径的要求是相反的。因此 Kiwi 采用**双模切换**：共享同一份知识数据，但各自拥有独立的页面骨架、导航结构、视觉基调和交互范式。

### 4.2 模式切换机制

**切换入口**：全局顶栏左侧放置分段控件形式的**模式切换器**，两个选项"编辑 / 学习"。这是全系统最高层级的导航状态，优先级高于知识库切换器。切换时伴随约 300ms 的整页过渡动画。

**状态保持规则**：两套模式各自维护独立的会话状态，切换时互不重置：

| 状态 | 编辑模式 | 学习模式 |
|---|---|---|
| 当前知识库 | 独立记忆 | 独立记忆（可与编辑模式不同） |
| 打开的页面/会话 | 记忆最近打开的笔记或 Wiki 页面 | 记忆当前训练会话或仿真考试进度 |
| 面板布局 | 记忆侧边栏展开状态、编辑器视图模式 | 记忆学习面板的展开状态 |
| 滚动位置 | 记忆 | 记忆 |

**跨模式跳转**：

- **编辑 → 学习**：Wiki 页面和笔记的更多菜单中提供"针对本页发起学习"，切换到学习模式并以该页面为学习范围直接开始会话；
- **学习 → 编辑**：答题解析、整卷报告的引用处提供"查看源页面"，切换到编辑模式并定位到对应 Wiki 页面或原始素材；
- 跳转后目标模式接收来源上下文，但**不覆盖**目标模式原有的会话状态。

**可用性约束**：学习模式依赖 Wiki 页面和素材已建立索引。对于空知识库或尚无 Wiki 页面的知识库，学习模式入口可见但置灰，提示"请先在编辑模式导入素材并完成编译"。

### 4.3 编辑模式布局

编辑模式采用**三栏工作台**布局：

- **左侧栏**：笔记、Wiki、总览、导入、图谱、设置。当前视图高亮，支持折叠为图标栏。
- **主内容区**：承载当前视图。笔记编辑器提供全宽编辑、大纲、分屏、阅读四种视图切换；Wiki 浏览提供页面树 + 正文的双栏结构。
- **右侧辅助面板**：浏览 Wiki 时显示大纲与双向链接，编辑笔记时可唤出 AI 对话和来源引用。面板可折叠。

**视觉基调**：冷静、克制、信息优先。中性灰白背景，玻璃质感仅用于侧栏和辅助面板，正文区保持纯色高对比。动效以功能性为主。

**操作范式**：多线程、可中断、可回溯。可同时打开多个笔记标签；导入和编译任务在后台异步推进；任何操作可撤销或回退；快捷键体系完整；自动保存草稿。

### 4.4 学习模式布局

学习模式采用**聚焦式单任务**布局：

- **左侧栏**：今日复习、继续学习、仿真考试、错题本、学习图谱、学习计划。不出现笔记、导入、设置等编辑类入口。
- **主舞台**：一次只呈现一张卡片（一道题、一道案例题、一篇论文题、一份整卷分析报告或一段冷启动对话）。卡片居中，周围留白充足。答题后卡片翻转或滑出，下一张卡片滑入，形成明确的节奏感。
- **右侧面板**：掌握度环形图、SM-2 复习队列（到期/即将到期/未到期分组）、连续学习天数、本次会话正确率、学习计划进度。视觉权重低于主舞台。

**视觉基调**：专注、有节奏、有反馈感。背景更安静，主舞台卡片使用更明显的阴影和圆角。答题正确时轻微绿色脉冲，错误时柔和红色抖动，掌握度提升时环形图有填充动画。这些动效仅在学习模式启用。

**操作范式**：单线程、线性推进、有明确终点。一次只做一件事；推进路径由计划引擎和出题引擎调度；每次答题后立即反馈；会话有明确的开始和结束，结束后进入会话总结页。

### 4.5 共享与隔离的边界

**共享的数据**：知识库、素材、Wiki 页面、链接关系、检索索引、编译产物、模型配置完全共享。

**隔离的状态**：

| 状态 | 归属 | 说明 |
|---|---|---|
| 编辑器打开标签、光标位置、视图模式 | 编辑模式独有 | 学习模式不感知 |
| 学习画像、训练会话、仿真考试进度 | 学习模式独有 | 编辑模式不感知 |
| 掌握度、复习调度、错题本、仿真试卷 | 学习模式独有 | 编辑模式的 Wiki 总览中只读展示掌握度热力覆盖 |
| 个人批注 | 学习模式独有 | 与 Wiki 正文分离存储，编辑模式可只读查看但不可编辑 |
| 联网核查日志 | 学习模式独有 | 仅作为题目来源参考，不进入知识库 |
| 模式偏好 | 全局 | 下次打开系统时恢复上次所在模式 |

**关键规则**：学习模式产生的数据（画像、掌握度、错题、试卷、批注、联网日志）**不回写 Wiki 正文、不触发编译、不改变人工编辑标记**。编辑模式产生的数据会影响学习模式的内容来源，但不重置已有掌握度——掌握度绑定知识点标识，知识点内容更新后掌握度保留，但标记"内容已更新，建议重新学习"。

### 4.6 模式切换的边界情况

| 场景 | 处理 |
|---|---|
| 编辑模式有未保存草稿时切换 | 自动保存草稿，切换不丢失；返回时恢复光标位置 |
| 学习模式训练中途切换 | 当前题目状态保留，返回时从同一题继续；不判定为放弃 |
| 仿真考试中途切换到编辑模式 | 考试计时**暂停**并记录剩余时间；返回后继续计时。这是个人场景的便利性设计，与真实考试有差异，在考试须知中明确说明 |
| 学习进行中后台编译完成 | 学习模式不弹通知；在会话总结页或返回编辑模式后提示 |
| 学习范围对应的 Wiki 页面被删除 | 相关知识点标记失效，掌握度保留但不再出题；已生成的仿真试卷不受影响 |
| 用户首次使用学习模式 | 进入冷启动对话界面 |
| 知识库为空或尚无 Wiki 页面 | 学习模式入口置灰，提示先完成导入与编译 |
| 连续学习时间过长 | 会话总结页温和提示休息，不强制中断 |

## 5. 数据模型

| `exam_templates` | id, name, is_builtin, question_types_json, scoring_rules_json, passing_criteria_json, duration_minutes, difficulty_distribution | 考试场景模板，内置 + 用户自定义 |
| `study_plans` | id, profile_id, phase, suggested_mode, plan_json, updated_at | 学习计划，每日重算 |
| `learning_topics` | id, kb_id, title, wiki_page_id?, raw_chunk_refs, mastery_score, sm2_state_json, prerequisite_topic_ids, exam_template_id, weak_flag | 学习知识点 |
| `learning_questions` | id, topic_id, question_type, difficulty_level, body_json, answer_json, generated_at, source_hash, web_sources_json, confidence_level, cache_status | 学习题目，记录联网来源和置信度 |
| `learning_attempts` | id, question_id, user_answer, llm_score, score_breakdown_json, mode, mock_exam_id, attempted_at | 答题记录，区分渐进/仿真形态 |
| `mock_exams` | id, profile_id, exam_template_id, generated_at, status, total_score, score_breakdown_json, time_spent_json | 仿真试卷 |
| `mock_exam_items` | mock_exam_id, question_id, order_index, score | 试卷题目快照 |
| `web_research_logs` | id, question_id, query, sources_json, verified_at | 联网核查日志 |
| `learning_annotations` | id, kb_id, target_type, target_id, content_md, created_at | 学习模式个人批注 |

### 5.2 数据隔离原则

`kb_id` 是贯穿数据、检索、模型三层的锚点。一个 `source`、`wiki_page` 或 `note` 只属于一个知识库，不做跨库共享。PostgreSQL 是业务事实源，Qdrant 是可重建的向量索引。

## 6. 知识库管理

### 6.1 知识库实体

用户可以创建多个知识库，每个知识库是独立的知识边界。知识库具备名称、描述、默认 Embedding 模型、默认大模型配置等属性。用户可以在界面全局切换当前知识库，笔记编辑、Wiki 浏览、素材导入、对话检索、学习模式默认作用于当前知识库。

知识库列表展示文档数、Wiki 页面数、笔记数、默认模型、学习画像状态（是否已冷启动）、最近活动等概览信息。知识库之间数据独立，不做跨库共享。

### 6.2 隔离策略

**PostgreSQL 层**：个人场景下，服务层在每次查询中强制注入 `kb_id` 条件，所有数据访问通过统一的 Repository 层封装，`kb_id` 作为必传参数，杜绝旁路查询。未来多用户扩展时可启用 PostgreSQL RLS 作为可选加固。

**Qdrant 层**：采用单 collection + payload filter 策略。在 `raw_chunks` 和 `wiki_pages` 两个 collection 的每个 point payload 中写入 `kb_id`，并为该字段创建 `is_tenant: true` 的关键字索引。`is_tenant` 标志会触发 HNSW 图在租户边界内的优化构建和查询时的租户过滤提前下推。检索时在 `query_filter.must` 中注入 `kb_id` 条件，**过滤在检索边界内执行，不做"先召回后过滤"**。

## 7. 笔记管理

### 7.1 参考的笔记工具与核心借鉴点

| 工具 | 核心设计特征 | 对 Kiwi 的借鉴价值 |
|---|---|---|
| **Notion** | 一切皆页面、页面由块组成，数据库提供表格/看板/日历等多种视图，模板预填新条目 | 笔记也可以是结构化数据行；同一批数据按不同视图呈现 |
| **Obsidian** | 本地 Markdown 文件夹 + 双向链接 + 图谱，标签克制使用，MOC 作为索引页 | 文件夹做粗分类、链接做知识网络；双向链接不依赖路径 |
| **Logseq** | 大纲式块结构、块引用/嵌入、白板、闪卡、高级查询 | 块级引用让笔记最小单位从"页面"下探到"段落" |
| **Heptabase** | 以"地图 → 白板 → 卡片"为层级，卡片可在无限白板上自由拖拽和连接 | 为笔记提供视觉化组织的补充维度 |
| **Craft** | 同时支持文件夹、标签、双向链接、集合多种组织方式 | 印证混合组织是个人知识库的务实选择 |
| **语雀** | 知识库 → 目录 → 文档的层级结构，目录驱动浏览 | 中文用户对层级目录的天然熟悉度 |

### 7.2 四种组织维度并存

**文件夹（层级目录）**：每个知识库内部维护一棵笔记文件夹树，支持多级目录。文件夹承担粗粒度分类的职责——按项目、主题、来源或时间阶段划分。浏览时左侧以可折叠的树形结构呈现。文件夹不参与链接语义：笔记之间的双向链接不依赖所在路径，移动文件夹不会破坏已有链接。

**标签**：用于表达跨主题的横切属性。采纳"克制"原则：标签数量建议控制在 3–5 个核心标签层级，支持嵌套层级（如 `#项目/前端`），并可在侧栏中按使用频率和最近使用排序。文件夹与标签的分工明确：**文件夹回答"这篇笔记放在哪"，标签回答"这篇笔记是什么"**。

**双向链接与反向链接**：笔记正文支持 `[[笔记标题]]` 格式的双向链接。保存时系统自动建立链接关系，并在被链接笔记的右侧面板中呈现反向链接列表，附带引用上下文。双向链接的建立不依赖文件夹路径，也不要求用户预先规划好知识结构。

**笔记集合（Collection）**：一种轻量结构化笔记容器。用户可以把一批笔记组织成一个集合，并为集合定义属性字段（如状态、评分、日期、来源类型）。同一批笔记可以在列表视图、看板视图、日历视图之间切换，而不需要复制数据。集合中的每一行仍然是一篇完整的笔记，可以正常打开编辑、参与双向链接、出现在文件夹和标签筛选中。

### 7.3 创建与编辑入口

**快速捕获（Inbox）**：编辑模式左侧栏提供快速捕获入口——一个极简输入框，用户输入标题和几句话即可创建笔记，先落入默认的"收件箱"文件夹，不强制立即选择文件夹或标签。快速捕获的价值在于降低"记一笔"的心理门槛。

**从模板创建**：每个知识库可以维护一组笔记模板，在新建笔记时可选。模板预填标题结构、标签、属性字段和提示性占位块。常见模板包括：文献笔记（含来源、摘要、关键论点、个人评注）、会议记录（含日期、参与人、决议、待办）、概念卡片（含定义、示例、关联概念）、**学习笔记（含知识点、易错点、真题摘录、个人总结）** 。模板是知识库级别的资产。

### 7.4 浏览与检索

**多入口浏览**：文件夹树（默认入口）、标签面板（支持多标签组合过滤）、集合视图（列表/看板/日历）。三个入口作用于同一批笔记数据。

**全局搜索与筛选**：笔记搜索支持全文搜索，并可按知识库、文件夹、标签、笔记类型、创建/修改时间进行组合筛选。搜索结果展示匹配片段的高亮上下文。如果用户为笔记关联了 Wiki 页面或原始素材，搜索范围可扩展至这些关联内容。

**反向链接与"相关笔记"**：每篇笔记的详情页右侧辅助面板展示反向链接（直接引用当前笔记的其他笔记，附带引用上下文）和相关笔记（基于共享标签、共同引用的笔记或内容相似度推荐的笔记）。反向链接是用户主动建立的强关联，相关笔记是系统推断的弱关联，两者在视觉上区分。

### 7.5 元数据与生命周期

**标准元数据**：每篇笔记自动维护标题、创建时间、修改时间、所属文件夹、标签列表、关联的 Wiki 页面、关联的原始素材。

**自定义属性**：当笔记属于某个集合时，该集合定义的属性字段出现在笔记详情中。集合属性只在该集合的上下文中生效，不污染全局笔记模型。

**生命周期状态**：

| 状态 | 含义 | 行为 |
|---|---|---|
| **活跃** | 正常使用中的笔记 | 出现在常规浏览和搜索中 |
| **归档** | 已完成或不再频繁使用的笔记 | 从默认列表中隐藏，但保留在搜索和反向链接中；可随时取消归档 |
| **回收站** | 已删除的笔记 | 保留 30 天后自动清理，期间可恢复 |

### 7.6 与其他模块的衔接

**笔记 → Wiki 编译的素材**：笔记可以作为独立素材参与 LLM Wiki 编译。用户在笔记详情中可以选择"以此笔记触发编译"，系统将其视为一个 `source` 进入编译流水线。笔记的块级引用会作为编译的上下文一并传递。

**笔记 → 学习模式的锚点**：学习模式的知识点抽取以 Wiki 页面和原始素材为主，但用户可以手动将某篇笔记中的内容标记为"学习要点"，使其进入学习模式的出题范围。用户在渐进训练中积累的易错点笔记，可以关联到具体知识点，在复习时被引用。

**笔记 → 知识图谱的节点**：笔记作为图谱节点与 Wiki 页面共同出现在编辑模式的知识图谱中，笔记之间的双向链接构成图谱的边。图谱筛选器可以单独查看"仅笔记"的链接网络。

**与双模的边界**：笔记管理完全属于编辑模式。学习模式中不出现笔记的创建、编辑、归档入口，对笔记的访问是只读的，仅限于答题解析或报告中引用笔记内容时跳转查看。

## 8. 笔记编辑器

### 8.1 编辑内核

编辑器基于 Tiptap 的 Vue 3 封装构建，采用开箱即用的 NotionLike 预设，包含 Slash 命令（输入 `/` 唤起标题、列表、代码块等）、智能气泡菜单（选中文字浮现格式化工具栏）、块级拖拽手柄、大纲目录、Markdown 快捷键等基础能力。

### 8.2 知识库特有的块类型

**来源引用块**：从原始素材或 Wiki 页面拖入引用时，自动生成带来源标识和内容指纹的引用块，支持点击跳转到原文对应位置。

**AI 辅助块**：在编辑器中选中文本或输入 `/ai`，调用当前知识库绑定的 LLM 配置，执行"续写 / 缩写 / 翻译 / 基于知识库解释"等操作。AI 输出以可接受/拒绝的差异形式呈现在块内，而非直接改写用户文本。

**双向链接块**：输入 `[[` 触发 Wiki 页面自动补全，插入链接并同步写入链接关系表，使笔记成为知识图谱中可被检索和链接的节点。

**知识点关联块**（学习场景增强）：用户在写学习笔记时，可以将某个块标记为"关联知识点"，选择当前学习画像中的知识点关联。该块内容会在复习时作为"我的笔记"被引用，与 Wiki 原文一起辅助回忆。

### 8.3 多视图

| 视图 | 说明 |
|---|---|
| **编辑视图** | 全宽块编辑器，聚焦写作 |
| **大纲视图** | 左侧根据标题层级实时生成的大纲面板，滚动高亮，点击跳转 |
| **分屏视图** | 左编辑 / 右渲染预览，或左编辑 / 右 AI 对话（将当前文档作为上下文） |
| **阅读视图** | 隐藏工具栏和拖拽手柄，纯渲染 Markdown，适合长文回顾 |

视图状态持久化，按笔记 ID 记忆用户上次使用的视图。

## 9. LLM Wiki 编译

### 9.1 Schema 层：LLM 的"行为契约"

Schema 是 LLM Wiki 区别于普通 RAG 的关键设计。用一份独立的结构化文件定义：页面类型与模板（entity / concept / summary / synthesis）、slug 与 wikilink 规范、质量标准（最少交叉引用数、来源标注、矛盾标记格式）、ingest 指令（读取新源 → 检索关联页 → 更新或新建 → 记录 log）。Schema 作为文件加载并注入 LLM 上下文，便于迭代和版本管理。

### 9.2 异步摄入流水线

```
parse → chunk → embed_raw → retrieve_related_pages
     → compile_wiki → index_wiki → finalize
```

- **chunk**：保留标题层级和段落边界，不采用固定 token 切分。层级感知的切分对表格依赖问题有显著影响。
- **retrieve_related_pages**：用新源内容检索现有 Wiki 页面，确定本次编译应触及的 10–15 个页面。
- **compile_wiki**：LLM 按 Schema 输出新页面或对现有页面的 patch，尊重 `human_edited=true` 的页面不被覆盖。
- **index_wiki**：将编译后的 Wiki 页面嵌入存入独立的 `wiki_pages` collection，与 `raw_chunks` 分离，便于差异化检索权重。

**编译触发策略**：批量导入默认"仅入库不编译"，由用户按需挑选素材触发编译。增量编译采用"关联页定位"策略，只让 LLM 读写与新源相关的现有页面及可能新建的页面。全量 lint 和重索引按周或手动触发。

### 9.3 健康检查（Lint）

两遍 lint：

- **确定性扫描**：死链、孤立页面、frontmatter 完整性、slug 冲突、索引页一致性；
- **LLM 语义审查**：矛盾检测、知识缺口识别、源漂移检测（原始素材内容指纹变化时标记待重编译）。

Lint 配置为定时任务，前端提供手动触发入口。检查结果以报告形式呈现，用户可据此决定是否触发重编译或人工修正。

## 10. Wiki 总览与知识图谱

### 10.1 Wiki 总览

Wiki 总览是知识库的"编译产物仪表盘"：

- **统计卡片**：Wiki 页面总数、按类型分布、待编译素材数、待复核页面数、最近健康检查摘要、**学习画像状态（是否已冷启动、掌握度覆盖率）** ；
- **页面网格**：按类型分组的卡片视图，每张卡片显示标题、摘要首行、被链接次数、人工编辑标记、**掌握度热力边框（只读展示，来源学习模式）** ；
- **检索入口**：顶部的全局检索框，支持按标题、类型、标签过滤；
- **编译状态时间线**：最近 ingest 批次和编译活动的简要时间线。

数据来源全部是关系数据库的聚合查询，首屏不触发向量检索，保证加载延迟在百毫秒级。

### 10.2 知识图谱

以可视化方式呈现 Wiki 页面与笔记之间的链接网络：

- **节点**：Wiki 页面 + 笔记，按页面类型着色，节点大小映射被链接次数；
- **边**：引用、相关、矛盾标记，不同边类型用线型和颜色区分；
- **过滤**：按知识库、页面类型、人工编辑状态筛选；
- **交互**：点击节点跳转到对应页面；拖拽节点位置持久化；
- **性能边界**：节点数量较大时自动切换为性能模式，超过一定规模时降级为以当前节点为中心的 1–2 跳邻域视图。

### 10.3 学习图谱

学习模式的知识图谱是编辑模式图谱的"掌握度视图"：节点颜色深浅表示掌握度，突出前置关系与待复习节点。与编辑模式图谱共享同一份链接数据，但只读，不可拖拽布局。

## 11. 导入管道

### 11.1 统一 Import Adapter 架构

所有导入源（语雀、文件上传）输出统一的 **Import Item**：标题、Markdown 正文、来源 URL、原始标识、内容指纹、本地资源清单、解析质量。后续复用同一套异步摄入流水线。

### 11.2 语雀导入

**路径 A（推荐）：令牌直连。** 用户填入语雀访问令牌，后端调用语雀开放接口拉取知识库列表、目录树和文档内容。语雀的 Lake 格式需转换为标准 Markdown。接口限流通过串行拉取 + 退避处理，导入任务异步化。

**路径 B（兜底）：导出包导入。** 语雀网页端支持导出 Markdown 压缩包，适配器解压、解析目录结构、提取元数据，复用同一套归一化逻辑，不消耗接口配额。

**关键限制**：语雀开放接口不提供附件导出。令牌模式下附件保留原始链接；需要完整附件时建议使用导出包路径。

**增量重导入**：以原始文档标识为幂等键。再次导入时比对更新时间，只更新有变化的文档。用户手工编辑过的 Wiki 页面不被覆盖，仅更新原始素材并标记源漂移。

### 11.3 文件上传导入

**上传协议**：小文件直传；大文件分片上传 + 断点续传，合并后计算内容指纹作为幂等键。

**三层安全校验**：
1. **真实类型检测**：读取文件头检测真实类型，维护严格白名单，拒绝可执行文件和 HTML；
2. **病毒扫描**：内存扫描不落盘，扫描异常状态不得当作干净放行；
3. **压缩炸弹防护**：办公文档本质是压缩容器，设置解压后总大小和嵌套深度上限。

**解析引擎路由**：
- **办公文档**：优先使用版面还原能力强的解析器，无需加载 AI 模型，速度快；
- **电子原生 PDF**：优先高精度解析器，纯文本快速路径作为备选；
- **扫描件 PDF**：自动降级到 OCR（中文场景优先中文 OCR 引擎）；
- **纯文本 / Markdown**：原生透传，仅注入元数据。

**解析质量分级**：干净 / OCR 辅助 / 待人工复核。低置信度 OCR 或表格结构异常标记为待复核，前端高亮提示用户手动检查。

**编译模式**：文件上传默认"仅入库，不编译"，避免批量拖入数十个 PDF 触发成本失控；用户可显式选择"入库并编译"。

**批次管理**：素材按导入批次组织，前端可查看批次的解析状态、质量分布和编译进度，完成后生成导入报告。

## 12. 检索与问答

### 12.1 检索范围

| Scope | 语义 | 过滤条件 |
|---|---|---|
| **单库** | 只在选定的一个知识库内检索 | `kb_id == selected_kb` |
| **多库** | 在勾选的多个知识库内检索 | `kb_id IN (selected_kbs)` |
| **全局** | 在有权访问的全部知识库内检索 | 无 `kb_id` 约束（或 `kb_id IN (accessible_kbs)`） |

Scope 由前端在请求中传入，后端**在检索边界内强制执行**，这是防止跨库数据泄露的安全底线。

### 12.2 融合排序

当查询命中多个知识库时，各库返回的原始相似度分数**不可直接横向比较**。采用 **RRF（Reciprocal Rank Fusion）** 按排名融合，不需要对不同查询的得分做归一化，延迟低、效果稳定。如果各知识库使用相同的 Embedding 模型，则可直接比较余弦相似度，无需 RRF。

### 12.3 意图路由与上下文组装

轻量分类判断查询走 **Wiki 优先**（概念解释、综合对比）还是 **Raw 优先**（精确引用、事实核验）。Wiki 优先路径检索 `wiki_pages` collection 并沿链接关系扩展 1–2 跳；Raw 优先路径检索 `raw_chunks`，必要时关联 Wiki 摘要作为补充。全局 Scope 下，引用卡片标注来源知识库名称，便于用户判断出处。

### 12.4 流式输出

回答以流式方式逐字呈现，引用的每条来源标注所属知识库和页面，用户可点击跳转到对应 Wiki 页面或原始素材。导入、安全扫描、解析、编译四个串行阶段共用一个事件流订阅通道。

**查询回写（可选）** ：有价值的多源综合回答，经用户确认后可回写为新的 Wiki 综合页面。

## 13. 大模型配置

### 13.1 三层优先级

**全局默认 → 知识库默认 → 页面级临时指定**：

- **全局默认**：系统兜底配置；
- **知识库默认**：该库的 ingest 编译和默认问答使用此模型；
- **页面级临时指定**：用户在对话或 Wiki 页面通过模型选择器临时覆盖本次请求，**不改变知识库持久配置**。

请求级覆盖作为参数传入后端，优先级最高，仅对当前请求生效。批量 ingest、定时 lint、学习模式的出题与判分使用知识库默认模型，不弹出模型选择——**学习模式尤其需要避免分心去调模型**。

### 13.2 密钥安全

访问密钥加密后存入数据库，解密密钥来自环境变量，**解密仅在服务端工厂内部发生，绝不将明文密钥返回前端或写入日志**。如果加密/解密失败，应显式抛出错误而非静默降级为明文。前端只显示掩码，编辑时不修改密钥则保留原值。

### 13.3 测试连接

保存配置前提供连通性测试：用最小调用验证密钥有效性和模型可达性，返回成功/失败及错误类型（无效密钥、限流、模型不存在），避免不可用配置在 ingest 或学习出题阶段才暴露。

### 13.4 运行时动态实例化

服务端按优先级链解析目标配置，解密密钥后动态实例化模型客户端，注入编译、问答、出题、判分、组卷链路。支持在运行时切换模型和服务商，无需更改代码。

## 14. 学习模式

### 14.1 核心理念

学习模式的目标不是"让用户做够多少题"，而是**让用户在目标场景下真正具备通过考试或掌握知识的能力**。因此 Kiwi 的学习模式以三个原则组织：

- **以终为始**：学习过程对齐用户真实的目标场景（考试类型、题型结构、时长、评分规则），而不是抽象地"刷知识点"；
- **画像驱动**：所有出题、判分、调度决策都基于学习画像（当前水平、目标、历史表现、掌握度），而非固定题库或随机抽题；
- **动态生成**：题目由大模型按需生成，结合知识库内容、用户薄弱点和目标场景的题型要求，必要时联网核查事实性内容，保证题目正确性。

与传统题库产品的根本区别在于：**题库不是预先固定的资产，而是根据用户状态实时计算的产物**。缓存只是为了降低重复生成的成本，缓存失效与更新由内容变化和用户反馈驱动。

### 14.2 学习冷启动：对话式需求采集

用户首次进入学习模式（或为某个知识库首次发起学习）时，系统不直接出题，而是先进入**冷启动对话**，由大模型以引导式问答采集学习需求。

#### 14.2.1 采集内容

| 维度 | 采集问题示例 | 用途 |
|---|---|---|
| **学习目标** | "你这次学习是为了通过某个考试，还是想系统掌握某个领域？" | 决定是否启用考试场景模板 |
| **目标考试/领域** | "考试名称是什么？比如软考高项、中项、PMP、考研专业课" | 匹配考试场景模板 |
| **当前水平** | "之前接触过这部分内容吗？做过真题吗？大概什么水平？" | 初始化掌握度先验、决定起始难度 |
| **时间约束** | "距离考试还有多久？每天大概能投入多少时间？" | 制定学习计划、决定训练节奏 |
| **薄弱环节自述** | "你觉得自己哪部分最没把握？" | 初始化知识点优先级 |
| **输出形式偏好** | "你希望平时一题一题练，还是希望做整套模拟卷？" | 决定初始形态（系统仍会在后期动态调整） |

对话不是一次性问卷，而是**渐进式引导**：系统根据用户回答追问关键缺口，用户也可以跳过问题。对于已通过编辑模式绑定知识库的用户，系统会说明"你的知识库里有 N 个 Wiki 页面、M 篇原始素材，我会以这些内容为主要出题依据"，让用户对学习范围有预期。

#### 14.2.2 冷启动产出：学习画像

对话结束后，系统生成结构化**学习画像**，包括：

- 目标类型（考试 / 领域掌握 / 兴趣探索）；
- 目标场景（若为考试，关联到具体考试场景模板）；
- 水平先验（新手 / 有基础 / 进阶），用于初始化掌握度与起始难度；
- 时间预算（目标日期、每日可投入时长）；
- 薄弱环节标签（用户自述 + 系统从知识库内容推断）；
- 初始形态偏好（渐进式 / 仿真 / 由系统决定）。

学习画像在设置页可查看和修改。用户在中途改变目标（如换考试、延期）时，计划引擎会重新计算，已积累的掌握度保留。

#### 14.2.3 非冷启动场景

- **已有画像、新增知识库**：仅补充采集与该知识库相关的范围问题，不重复采集目标信息；
- **快速开始**：用户可跳过冷启动，系统使用默认画像（领域掌握型、无时间约束、渐进式起步），后续在会话中逐步补全；
- **画像变更**：用户主动修改目标场景时，系统提示"题型结构将随之变化，已掌握的通用知识点不受影响，考试特有题型需重新适应"。

### 14.3 考试场景模板

考试场景模板（Exam Template）是学习模式的**场景契约**，定义了"这场考试长什么样"，学习过程的题型结构、时长、评分规则都以此为准。

#### 14.3.1 模板内容

| 要素 | 说明 |
|---|---|
| **考试名称与简称** | 如"信息系统项目管理师（高项）" |
| **题型清单** | 每种题型的名称、数量、分值、时长 |
| **题型结构** | 各题型的占比与顺序 |
| **评分规则** | 客观题按对错；主观题按评分维度与权重（如案例题按"问题定位、原因分析、措施建议"给分） |
| **合格标准** | 总分合格线、单科合格线（如软考各科均需 45 分以上） |
| **难度分布** | 各题型内部的基础/理解/应用比例 |
| **知识点覆盖要求** | 考试大纲对应的知识域，用于组卷时的覆盖度检查 |

#### 14.3.2 内置模板与自定义

系统内置常见考试场景模板，用户可直接选用：

| 场景 | 题型结构 |
|---|---|
| **软考高项（信息系统项目管理师）** | 综合知识（75 道选择）+ 案例分析（3 道主观题）+ 论文（1 篇） |
| **软考中项（系统集成项目管理工程师）** | 综合知识（75 道选择）+ 案例分析（3–4 道主观题），**无论文** |
| **PMP** | 180 道情景选择题 |
| **考研专业课 / 领域掌握** | 默认按"选择 + 简答"两题型组织，用户可自定义 |

用户也可以**自定义考试场景模板**：指定题型清单、数量、分值、时长和评分维度。自定义模板保存后可复用。

**场景适配的关键**：学习过程中生成的题目类型严格对齐模板。选择高项的用户会训练论文写作（LLM 按论文评分维度给出反馈），选择中项的用户不会遇到论文题。这避免了"用同一套题目应付不同考试"的失真。

### 14.4 动态出题引擎

#### 14.4.1 出题依据的四类输入

1. **知识库内容**：Wiki 页面优先（结构清晰、交叉引用完整），raw chunks 补充（覆盖尚未编译的素材）；
2. **学习画像**：目标场景、当前水平、时间约束、薄弱环节自述；
3. **掌握度状态**：各知识点当前掌握度、最近作答正确率趋势、错题分布；
4. **场景模板**：当前训练形态（渐进式 / 仿真）对应的题型结构、难度分布、覆盖度要求。

#### 14.4.2 渐进式训练的即时出题

渐进式训练每次生成一道题或一小批题（3–5 道），出题逻辑：

- **优先覆盖薄弱点**：掌握度低、近期错题集中的知识点优先出题；
- **尊重前置关系**：前置知识点未达掌握阈值的，先出前置题，暂缓后续知识点；
- **难度自适应**：连续答对则提升难度层级，连续答错则回退并补充同层级练习；
- **题型轮换**：按场景模板的题型占比轮换（如高项用户的选择题与案例题交替出现）；
- **避免重复**：近期已出过的相似题目不重复生成，通过题目指纹去重。

#### 14.4.3 仿真考试的组卷

仿真考试需要一次性生成**整卷**，组卷逻辑与即时出题不同：

- **按模板配题**：严格按场景模板的题型、数量、分值组卷；
- **覆盖度检查**：组卷前计算知识域覆盖度，确保试卷覆盖大纲要求的主要知识域，而非集中在少数页面；
- **难度分布控制**：按模板定义的基础/理解/应用比例分配题目难度；
- **整卷锁定**：试卷生成后锁定，考试期间不因用户作答情况动态调整（模拟真实考试）；
- **交卷后统一判分**：客观题即时判分，主观题由大模型按评分维度评估，最后给出整卷得分、各题型得分、知识点雷达图和逐题解析。

#### 14.4.4 联网核查与正确性保障

涉及事实性内容的题目（法规条款、标准编号、具体数据、时间节点、行业规范）存在大模型"编造"的风险。出题引擎在以下情况触发**联网查询**：

- 题目涉及具体的法规、标准、政策条款；
- 题目涉及可验证的数字、日期、版本号；
- 题目内容超出知识库素材范围，需要外部资料补充；
- 用户主动对某道题提出"内容存疑"的反馈。

**联网核查的流程**：出题引擎调用搜索工具检索权威来源（官方网站、标准发布机构、权威教材），交叉验证后生成题目，并在题目卡片上标注"参考来源"链接。多源结果不一致时，优先采用权威源，并在题目上标注"存在不同说法，以官方为准"的提示。

**联网结果的使用边界**：联网获取的资料**不自动写入知识库**，不触发 Wiki 编译，不改变原始素材。它仅作为题目生成的参考依据，以"参考来源"形式附在题目上供用户核对。如果用户认为外部资料有价值，可以主动将其作为素材导入知识库，走正常的入库与编译流程。这避免了外部内容污染用户精心维护的知识库。

**低置信度处理**：如果联网核查后仍无法确认题目的事实准确性，该题标记为"待核实"，在题目卡片上明确提示用户，并降低其在判分中的权重。用户可对"待核实"题目提交纠错反馈。

#### 14.4.5 题目缓存与失效

- **缓存策略**：渐进式训练的题目生成后短期缓存（如同一会话内），避免重复生成；仿真试卷生成后长期缓存，供用户重做和复盘；
- **失效条件**：关联 Wiki 页面内容发生变化（源漂移）、用户对题目提交纠错反馈、考试大纲或场景模板更新；
- **失效后的处理**：标记缓存失效，下次使用时重新生成；已产生的答题记录保留，用于掌握度计算的历史追溯。

### 14.5 双形态学习

#### 14.5.1 渐进式训练（Drill Mode）

**适用场景**：学习前期、知识点分散、需要逐个击破的阶段。

**特征**：

- 一次一题或一小批题，节奏轻快；
- 即时反馈：答完立即判分、给出解析、引用原文；
- 答错后自动追问变式题（同知识点的不同角度），直至掌握；
- 掌握度实时更新，热力图即时变化；
- 会话有明确终点：完成一组（10–15 题）或复习队列清空后进入总结页。

**界面**：单卡片居中，左侧迷你图谱导航，右侧掌握度与复习队列。干扰最小化。

#### 14.5.2 仿真考试（Mock Exam Mode）

**适用场景**：学习后期、临近考试、需要检验整体水平和时间管理能力的阶段。

**特征**：

- 按考试场景模板组卷，题型、数量、分值、时长与真实考试一致；
- 考试期间**不提供即时反馈**，不显示解析，模拟真实考场；
- 计时器全程显示，时间到自动交卷；
- 主观题（案例、论文）支持富文本作答，论文题提供字数统计与结构提示；
- 交卷后统一判分：客观题即时出分，主观题由大模型按评分维度评估（如案例题按"问题定位准确性、原因分析完整性、措施可行性"分别给分）；
- 生成**整卷分析报告**：总分、各题型得分、知识点雷达图、时间分配分析、逐题解析、薄弱知识点清单。

**论文题的特殊处理**（高项场景）：大模型按论文评分维度（切题度、论点完整性、论据充分性、结构逻辑、语言表达）逐项评估，给出分项得分和改进建议，并引用知识库中的相关 Wiki 页面作为"可补充的论据素材"。

#### 14.5.3 两种形态的关系

两种形态共享同一套知识点体系、掌握度数据和题目生成引擎，区别仅在于训练节奏和反馈时机：

| 维度 | 渐进式训练 | 仿真考试 |
|---|---|---|
| 出题粒度 | 单题或小批 | 整卷 |
| 反馈时机 | 即时 | 交卷后 |
| 时长 | 每 5–10 分钟一组 | 按模板定义（如 150 分钟） |
| 主要作用 | 知识吸收与巩固 | 水平检验与应试训练 |
| 掌握度更新 | 每题后更新 | 交卷后批量更新 |

用户在两种形态间的切换是自由的，但计划引擎会给出建议。

### 14.6 学习计划动态决策

计划引擎（Study Planner）负责在"渐进式训练"与"仿真考试"之间做出建议，并根据用户实际进度动态调整。

#### 14.6.1 决策依据

| 信号 | 含义 |
|---|---|
| **掌握度覆盖率** | 目标知识域中达到掌握阈值的比例 |
| **正确率趋势** | 近 N 题的移动平均正确率，判断水平是否稳定 |
| **错题集中度** | 错题是否集中在少数知识点，判断是否还有明显短板 |
| **剩余时间** | 距目标日期的时间，判断是否需要加快节奏 |
| **仿真考试历史表现** | 已完成仿真卷的得分与时间管理情况 |
| **用户手动选择** | 用户明确要求某种形态时，计划引擎让位 |

#### 14.6.2 阶段化建议策略

| 阶段 | 判断条件（示意） | 建议形态 |
|---|---|---|
| **初期** | 掌握度覆盖率 < 40%，或存在大量未接触知识点 | 渐进式训练为主，重点补齐基础 |
| **中期** | 覆盖率 40%–70%，正确率趋势上升但仍有波动 | 渐进式为主，穿插小规模专项练习（如只做案例题） |
| **后期** | 覆盖率 > 70%，正确率稳定，距考试 2–4 周 | 仿真考试为主，逐步增加整卷频率 |
| **冲刺** | 距考试 < 2 周 | 高频仿真 + 错题复盘，不再引入新知识点 |

**动态调整**：计划引擎每日根据最新状态重新计算建议。如果用户在仿真考试中得分明显低于预期，引擎会建议回退到渐进式训练补强薄弱点；如果渐进式训练的正确率连续多组超过阈值，引擎会提示"可以尝试一次仿真考试检验水平"。

**用户自主权**：建议不等于强制。用户随时可以手动选择形态，计划引擎记录用户选择并调整后续建议的倾向。对于"我只想做模拟卷"的用户，系统尊重其选择，但会在整卷分析中提示薄弱点。

#### 14.6.3 计划的可视化

学习模式右侧面板展示**学习计划进度**：目标日期倒计时、掌握度覆盖率进度条、建议形态徽标（"当前建议：仿真考试"）、本周计划（如"3 次渐进训练 + 1 次仿真"）。用户可以在计划视图中查看未来两周的节奏安排，并手动调整。

### 14.7 掌握度、判分与调度

#### 14.7.1 掌握度模型

每个知识点维护 0–1 的掌握度分数，初始值由冷启动的水平先验决定（新手 0，有基础 0.3，进阶 0.5）。每次作答后，结合判分结果和题目难度更新掌握度。掌握度是出题优先级、渐进逻辑、计划引擎的共同数据源。

**内容更新的处理**：掌握度绑定知识点标识而非内容指纹。知识点内容更新后掌握度保留，但标记"内容已更新，建议重新学习"。

#### 14.7.2 判分规则

| 题型 | 判分方式 |
|---|---|
| 选择题 / 判断题 / 填空题 | 规则判分，即时出分 |
| 简答题 / 案例题 | 大模型按评分维度分项打分，给出总分和逐项反馈 |
| 论文题 | 大模型按论文评分维度分项打分，给出改进建议和可补充论据 |

主观题判分时，大模型会引用知识库中的原文作为评分依据，解析中展示引用来源，用户可点击跳转核对。这既提升了判分的可信度，也让解析本身成为学习材料。

**判分反馈的纠错通道**：用户可对判分结果提交异议（如"我的答案也覆盖了这个要点"），系统记录反馈，并在后续判分中参考该用户的表达习惯。这是个人场景下的轻量个性化，不做复杂的模型微调。

#### 14.7.3 间隔复习调度

每个知识点关联复习调度状态（难度因子、间隔、重复次数）。完成一个知识点的题目后，根据作答质量计算下次复习日期。"今日待复习"队列由到期时间驱动。仿真考试中答错的知识点，复习间隔重置为最短，优先进入次日复习队列。

### 14.8 学习模式界面

#### 14.8.1 整体布局

学习模式采用聚焦式单任务布局，左侧学习导航、中栏主舞台、右侧进度面板。导航项包括：

- **今日复习**：到期的知识点队列；
- **继续学习**：恢复上次渐进式训练会话；
- **仿真考试**：进入仿真考试列表（历史试卷、新建试卷）；
- **错题本**：按知识点和题型筛选的错题集合；
- **学习图谱**：掌握度着色的知识网络；
- **学习计划**：目标日期、覆盖率进度、形态建议、周计划。

#### 14.8.2 冷启动对话界面

首次进入学习模式时，主舞台呈现对话式引导，系统提问、用户回答、逐轮推进。对话结束后展示生成的学习画像摘要卡片，用户可确认或修改后开始第一组训练。用户也可以选择"跳过，直接开始"，系统使用默认画像。

#### 14.8.3 渐进式训练界面

单卡片居中，卡片内容包含：题型徽标、难度标识、题干、作答区、参考来源（如联网核查过）、提交按钮。答完后卡片翻转展示判分结果、解析、引用原文链接、"再来一道同知识点的变式题"按钮。

#### 14.8.4 仿真考试界面

- **考前**：试卷概览卡片（题型结构、题量、时长、合格标准），"开始考试"按钮；
- **考中**：顶部计时器与进度条，左侧题号导航（标记已答/未答/存疑），主区域为当前题目，底部"上一题/下一题/交卷"；交卷前提示未答题目数量；
- **考后**：整卷分析报告页，包含总分、各题型得分、知识点雷达图、时间分配分析、逐题解析（可展开）、薄弱知识点清单及"针对薄弱点开始训练"按钮。

#### 14.8.5 个人批注

学习模式中浏览 Wiki 页面时可添加个人批注。批注属于学习记录，不写回 Wiki 正文，不与人工编辑标记混淆。编辑模式可只读查看批注，但不可编辑。

### 14.9 学习模式的边界情况

| 场景 | 处理 |
|---|---|
| 冷启动对话被跳过 | 使用默认画像（领域掌握型、无时间约束、渐进式起步），在后续会话中逐步补全 |
| 目标场景模板变更 | 已掌握的通用知识点保留，考试特有题型需重新适应；提示用户影响范围 |
| 知识库内容不足以生成某题型 | 如高项论文题需要足够的项目管理实践素材，若知识库素材不足，提示"建议补充相关素材"并提供联网资料作为临时参考 |
| 联网核查失败 | 题目仍可生成，但标记"未联网核实"，降低判分权重，提示用户自行核对 |
| 仿真考试中途退出 | 试卷状态保留，可续考；超过模板时长未交卷则自动交卷 |
| 学习范围对应的 Wiki 页面被删除 | 相关知识点标记失效，掌握度保留但不再出题；仿真试卷不受影响（已锁定） |
| 用户连续学习时间过长 | 会话总结页温和提示休息，不强制中断 |
| 用户在仿真考试中查答案 | 个人场景不做防作弊，但考后分析中会标注"答题时间异常"供用户自省 |

### 14.10 双模边界（学习模式侧）

学习模式产生的数据（学习画像、掌握度、错题、仿真试卷、批注、联网核查日志）**不回写 Wiki 正文、不触发编译、不改变人工编辑标记**。编辑模式可以只读查看掌握度热力图和批注，但不可编辑。学习模式中的联网资料**不自动进入知识库**，用户需主动导入才走正常入库流程。

## 15. 视觉与动效体系

### 15.1 视觉基调

Kiwi 采用 **Glassmorphism（毛玻璃）+ 冷紫灰调色板**，而非饱和度拉满的"赛博朋克"。半透明 tint、细边框和柔和阴影建立层次。玻璃效果应服务于"面板与背景的层次区分"，而不是让每个卡片都反光。

**落地原则**：仅对常驻面板（侧边栏、辅助面板、弹层）启用玻璃效果，正文编辑区保持纯色高对比背景。编辑模式视觉偏冷静克制，学习模式视觉偏专注有节奏，两者通过背景饱和度、卡片阴影和动效语言区分。

### 15.2 动效库选型

| 场景 | 选型 | 理由 |
|---|---|---|
| **应用内交互 / 布局动画** | Motion for Vue | MIT 协议，Vue 原生支持，声明式动画 |
| **复杂时间线 / SVG 形变** | GSAP（按需引入） | 时间线控制能力最强；注意许可证边界 |
| **视觉组件（背景、文字动效、3D）** | Inspira UI | 可复制组件，提供 Aurora 背景、Morphing Text 等 |
| **列表重排 / 块拖拽过渡** | AutoAnimate 或 Vue TransitionGroup | 零配置布局动画 |
| **页面级路由过渡** | CSS View Transitions | 浏览器原生，零 JS 开销 |

### 15.3 性能红线

- 只对 `transform` 和 `opacity` 做动画，**禁止动画 `width/height/top/left`**；
- 入场 `ease-out` 约 300ms，出场 `ease-in` 约 200ms；
- 全局尊重 `prefers-reduced-motion`，关闭非必要视差和粒子效果；
- `will-change` 只在动画前临时添加，结束后移除；
- 长列表（Wiki 总览、素材列表、对话记录）采用虚拟滚动；知识图谱、编辑器、视觉组件按路由懒加载；首屏不触发向量检索。

### 16.2 一键启动流程

| 联网检索 | 搜索工具 API（如 SearXNG 自建 / 商业搜索 API） | 出题事实性核查，可替换 |

## 18. 关键业务规则

| 规则 | 说明 |
|---|---|
| **知识库边界不可逾越** | 任何检索、问答、学习模式的检索范围都必须严格限定在用户选择的知识库内；全局检索仅覆盖用户有权访问的全部知识库 |
| **原始素材不可变** | 导入的素材内容不被修改，变更检测通过内容指纹进行；Wiki 编译是对素材的派生，不修改素材本身 |
| **人工编辑受保护** | 用户手工编辑的 Wiki 页面标记为人工编辑，后续编译不覆盖，仅提示源已变化 |
| **批量导入默认不编译** | 无论语雀导入还是文件上传，默认仅入库；编译由用户显式触发或按需挑选 |
| **模型配置分层生效** | 页面级临时指定 > 知识库默认 > 系统全局默认；临时指定不改变持久配置 |
| **访问密钥不出后端** | 密钥加密存储，前端只见掩码；测试连接在保存前完成 |
| **解析质量可见** | 待复核的解析结果必须明确告知用户，不得静默入库 |
| **学习出题尊重前置关系** | 前置知识点未达掌握阈值时，暂缓后续知识点出题 |
| **检索范围是安全底线** | 知识库过滤在检索时强制生效，不采用"先召回后过滤"的做法 |
| **双模数据单向依赖** | 学习模式的数据不回写 Wiki、不触发编译、不改变人工编辑标记；编辑模式的数据不重置学习掌握度 |
| **笔记属于编辑模式** | 学习模式对笔记只读，不提供创建、编辑、归档入口 |
| **出题对齐目标场景** | 题目题型严格对齐用户选定的考试场景模板，不为高项用户生成无论文的训练、不为中项用户生成论文题 |
| **联网资料不进知识库** | 联网核查获取的资料仅作为出题参考，不自动写入知识库、不触发编译；用户主动导入才走正常入库流程 |
| **事实性题目必须可追溯** | 涉及法规、标准、数据、日期的题目必须标注参考来源或"待核实"状态，不得静默生成 |
| **仿真试卷锁定** | 试卷生成后内容锁定，不因作答情况或知识库更新而改变，保证复盘可追溯 |
| **计划建议不强制** | 计划引擎给出形态建议，但用户手动选择优先 |
| **冷启动可跳过** | 用户可跳过画像采集使用默认画像，后续渐进补全 |
| **掌握度跨内容更新保留** | 知识点内容更新不重置掌握度，仅标记"建议重新学习" |

## 19. 非功能性要求

### 19.1 体验与视觉

系统采用现代化视觉风格，以克制的半透明玻璃质感建立面板层次，正文编辑区保持纯色高对比以保证长文本可读性。动效分层：应用内交互使用轻量动画库，复杂时间线与视觉组件按需使用高级动效库，页面跳转优先使用浏览器原生过渡。所有动画只作用于透明度和位移变换，尊重系统的"减少动态效果"设置。

### 19.2 性能与稳定性

文档解析、编译、导入、出题、组卷、判分、联网核查等重任务全部异步执行，不阻塞界面交互。解析任务在独立资源池中运行并设置资源上限。导入、编译、考试组卷等长任务的进度通过统一的事件流推送给前端。向量索引视为可重建的派生数据，业务事实以关系数据库为准。

### 19.3 安全

文件上传经过真实类型校验、病毒扫描、压缩炸弹防护三道防线；扫描异常不得当作干净放行。解析进程禁止任意外部网络访问。大模型访问密钥加密存储，解密仅在服务端内部发生。对话与检索结果中的引用严格限定在用户选择的知识库范围内。联网核查仅向配置的搜索服务发起查询，不在题目生成过程中执行任意网页内容。

### 19.4 可维护性

解析引擎、大模型服务商、向量索引、搜索服务均设计为可替换组件，升级或替换不影响业务数据。每个素材记录解析引擎版本，便于溯源和批量重解析。数据库迁移有版本管理，启动脚本自动执行迁移。

## 21. 总结

Kiwi 的设计围绕一条主线展开：**以知识库为边界，以知识编译为质量上限，以检索保底为响应下限，以模型配置为驱动引擎，以双模切换承载知识生产与消费，以画像驱动的自适应学习实现价值延伸**。

数据层以 `kb_id` 为贯穿素材、Wiki、笔记、检索、模型、学习的一等标识，在关系数据库和向量索引两侧建立数据边界。检索层以知识库过滤为安全底线，以 RRF 融合处理跨库排序，以意图路由区分 Wiki 优先与原文优先。编译层以 Schema 为行为契约，以增量编译和健康检查维持知识库的长期质量。导入层将语雀和文件上传统一收敛为 Import Item，在不侵入核心摄入流水线的前提下获得多源接入能力。

体验层用**编辑模式**承载信息密集、多线程、可回溯的知识生产工作台，用**学习模式**承载干扰最小、单线程、有节奏的知识消费舞台。两套模式共享同一份知识数据，各自维护独立会话状态，切换无损。笔记管理以文件夹、标签、双向链接、集合四种维度并存；编辑器以块级内核和知识库特有块承载写作；Wiki 总览与知识图谱让编译产物可浏览、可连接。

学习模式以**"以终为始、画像驱动、动态生成"** 三条原则组织：冷启动对话把用户的真实目标（考试类型、水平、时间）转化为结构化画像；考试场景模板把"这场考试长什么样"固化为可复用的契约，让题型训练与真实考试对齐——高项用户练选择、案例、论文三类，中项用户练选择、案例两类；出题引擎结合知识库内容、掌握度和场景模板动态生成题目，涉及事实性内容时联网核查并标注来源，联网资料不污染知识库；双形态学习让前期以渐进式训练吸收知识、后期以仿真考试检验水平，计划引擎根据覆盖率、正确率趋势和剩余时间动态建议切换，但最终选择权在用户。

大模型访问密钥的加密存储和"解密仅在服务端内部发生"是不可妥协的安全底线；解析资源的隔离与解析器版本锁定是生产环境不可省略的运维边界；联网核查的"参考来源"标注与"待核实"状态是题目可信度的保障；一键启动脚本降低本地使用门槛，与生产部署分离避免误用。

**Kiwi 最终交付的，不是一个"能问答的笔记库"，而是一个知识会自我沉淀、自我维护、可被检验、可按目标场景持续学习的个人知识工作台。**
