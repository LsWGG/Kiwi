# 迭代计划

本文件是 Kiwi 的中期迭代路线图，用于约束「接下来做什么、按什么顺序做、什么不做」。版本功能记录仍以 [CHANGELOG.md](CHANGELOG.md) 为准。

- 制定日期：2026-10-21
- 适用范围：单人本地优先部署（PostgreSQL + Qdrant），后续按里程碑滚动修订
- 估算口径：单人全职投入；「周」按 5 个工作日计

## 1. 当前判断

Kiwi 的功能面已经完整：笔记工作区（文档 / 数据表 / 画布 / Notebook / 导入 / 链接）、三种编辑模式、编译流水线、结构化 Wiki、知识星图、检索问答、学习闭环与 Docker 部署均已落地。当前的主要短板不在功能数量，而在于：

1. **没有自动化测试与 CI**：`backend` 有 pytest 依赖但没有测试目录，前端没有测试脚本；编译、检索、加锁、待办同步等高风险链路只能靠手工回归。
2. **后台任务不持久**：导入、编译、KB 迁移使用进程内 `asyncio.create_task`，重启即丢，且没有重试与幂等。
3. **单体路由过大**：`backend/app/routers/notes.py` 曾约 4700 行、依赖函数内延迟导入；已在 M2 拆分为 11 个子路由（见第 7 节）。
4. **数据安全依赖手工**：备份与恢复只有文档中的命令，没有定时任务与恢复演练；应用本身无访问控制。
5. **检索只有向量一路**：缺少全文检索、重排与段落级引用；AI 能力集中在编译与问答，缺少行内写作辅助。
6. **部署一致性靠人记**：线上曾长期提供旧的前端构建，没有版本标识与不一致提示。

因此路线图遵循「先地基、后纵深」：先把测试、任务、备份、观测做扎实，再扩展检索、AI、学习与互操作能力。

## 2. 优先级与工作量

| 标记 | 含义 |
|---|---|
| P0 | 不做会持续放大回归与数据风险，优先完成 |
| P1 | 直接提升数据安全与可运维性 |
| P2 | 产品差异化能力，依赖 P0/P1 的稳定性 |
| P3 | 学习闭环与内容互操作 |
| P4 | 体验优化，可穿插进行 |

工作量：**S** ≤ 2 天，**M** ≈ 1 周，**L** ≥ 2 周。

## 3. 里程碑

### M1 · 工程地基（P0，2 周）

目标：让每一次改动都能被自动验证，让后台任务在重启后仍可恢复。

| 事项 | 内容 | 工作量 |
|---|---|---|
| 测试体系 | 后端单元测试覆盖纯逻辑：`note_lock`、`todo_sync`、`retrieval` 的 RRF/余弦融合、`splitter`、图注折叠、复习调度；集成测试使用真实 PostgreSQL + Qdrant 覆盖 tree/reorder/导入/编译的 API 契约 | L |
| 前端回归 | Playwright 冒烟：目录树拖拽（含根目录投放区）、密码锁、模板创建、编译进度、阅读/编辑切换；复用本次 Firefox/Chromium 双内核验证方式 | M |
| CI | GitHub Actions：`ruff` + `pytest` + `vue-tsc -b --noEmit` + `vite build` + Playwright 冒烟，PR 必过 | S |
| 后台任务持久化 | 新增 `jobs` 表与单 worker：导入、编译、KB 迁移改为可恢复任务，支持重试退避、幂等键、取消与「编译任务」页重试 | L |
| 可观测性 | 结构化日志 + request id；健康页展示 DB / Qdrant / LLM 连通性与最近失败；`/metrics` 暴露任务队列长度、编译耗时、LLM 延迟与失败率 | M |
| 部署一致性 | Vite 产出 `build-info.json`（commit、构建时间）；设置页显示前后端版本，不一致时提示；`deploy.sh` 打印构建哈希 | S |

验收：CI 全绿；模拟进程重启后任务可续跑；线上版本号与 `build-info.json` 一致。

### M2 · 稳定性与数据安全（P1，3 周）

| 事项 | 内容 | 工作量 |
|---|---|---|
| 拆分笔记路由 | 将 `notes.py` 拆为 `tree / crud / import / link / lock / revisions / tags / export` 子路由，业务逻辑下沉 service，移除延迟导入式的循环依赖 | L |
| 自动备份 | 定时 `pg_dump` + uploads + manifest，保留策略可配置；提供一键恢复脚本与恢复演练记录 | M |
| 可选访问控制 | 默认仅监听 `127.0.0.1`；提供访问令牌 / 反向代理密码两种接入方式；对 LLM、导入、代码执行接口加简单限流 | M |
| 操作审计 | 删除、清空回收站、跨库迁移、KB 重建写入审计日志，设置页可查看与导出 | S |
| 整库导出/导入 | `.kiwi.zip`：Markdown + 附件 + 元数据 + 学习记录，可用于迁移、归档与分享 | M |
| 上锁笔记静态加密 | 可选「加密存储」，密码派生密钥 + Fernet；明确提示丢失密码不可恢复 | M |

验收：恢复演练在测试栈完成一次全量还原；危险操作均可在审计日志中追溯；令牌开启后未授权请求返回 401。

## 4. 明确不做（Non-goals）

以下事项经产品判断后**不纳入本路线图**，后续版本也不实现，避免反复讨论：

1. **Token 成本面板**
   - 不做按模型 / 知识库 / 会话的 token 用量与费用统计，不做预算、账单或成本告警面板。
   - LLM 侧只保留运行指标：延迟、失败率、重试次数；不采集、不持久化计费数据。
2. **国际化（i18n）**
   - 界面保持中文单一语言，不引入 `vue-i18n`，不抽离文案 key，不提供语言切换。
   - README 的中英双语说明保持现状，不作为应用内多语言的依据。

## 5. 暂缓评估（非承诺）

以下方向与「单用户、本地优先」定位存在张力，暂不排期，待 M1–M3 完成后再评估：

- Yjs/CRDT 实时协作、评论与 @提醒
- 多用户账号体系与细粒度权限
- 端到端加密的多端同步
- 插件 / 区块注册机制与模板市场

## 8. 完成定义（DoD）

每个事项合入 `main` 前需满足：

- `ruff`、`pytest`、`vue-tsc -b --noEmit`、`vite build` 全部通过；
- 新增或修改的关键路径有自动化测试，或在测试栈完成手工回归并记录；
- 涉及数据模型变更时提供 Alembic 迁移与回滚验证；
- 更新 [CHANGELOG.md](CHANGELOG.md)，必要时同步 [DEPLOY.md](DEPLOY.md)；
- 用户可见的变更附截图或录屏，写入对应的回归记录。
